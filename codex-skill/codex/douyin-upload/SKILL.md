# 抖音视频上传

用普通 Playwright 脚本一次跑完上传。封面由视频制作环节提供，只读取现成文件，不生成、不裁切、不等待生成。

## 最短可靠流程

1. 一次读取项目清单、成片和封面。没有清单时，从已有选题和文案整理发布字段，不重做视频内容。只检查一次文件存在和清单顺序，不重跑成片质量验收。
2. 复用已登录 Chrome context 或持久化 profile。一个协调进程，默认 4 个页面并发准备，按集数串行发布。**上传页不选择合集，全部提交后由一个页面统一补齐、排序并保存合集一次。** 即使串行点击发布，各并行页面里的旧合集列表仍可能互相覆盖。
3. 使用 `setInputFiles` 直接提交文件路径，批量完成填写和发布。不逐步截图、不逐次确认、不用 Computer Use 点击文件选择器。脚本内的并发是真正并行，不必为每次点击派一个子 Agent；委派时仅分配独立页面准备，共用一个发布与合集协调者。
4. 最后刷新后台核对一次。跳转到管理页只记 `submitted`；后台显示已发布才记 `published`，审核中如实报告。更新状态文件后结束，不能用 toast 或脚本仍在运行作为完成证据。

用户已经要求“上传/发布这些视频”时，在授权范围内执行，不再逐条请求批准。默认公开、立即发布；这个用户的声明偏好为“无需添加自主声明”，当次明确要求优先。这是用户偏好，不是平台规则。

## 字段约定

- 标题表达具体内容；合集已有集数时，去掉标题中重复的“第 X 集”。按清单 `episode` 排序，不按目录的字符串顺序猜集数。
- 文案保留已有正文。话题须点击候选菜单成为真实标签；已跑通的页面上限为 5 个，默认选 5 个相关话题，可提供额外相关候选。不机械补无关热门词，不把纯 `#文字` 当作选中话题。
- 竖封面 3:4、横封面 4:3 分别使用已提供文件。等可见预览和封面来源实际更新后再完成；不要等隐藏画布，也不要提前提交旧封面。
- 缺少视频或封面时，明确指出缺少哪个文件，不启动生成流程。没有指定合集时不擅自分类。此脚本处理已有合集；创建合集另按当次授权和现成合集封面处理。

## 使用

清单格式、本机现有会话及运行方式见 [references/runtime.md](references/runtime.md)。入口：`scripts/upload.mjs`。

```bash
node "$SKILL/scripts/upload.mjs" --manifest /absolute/path/upload.json --plan
node "$SKILL/scripts/upload.mjs" --manifest /absolute/path/upload.json --profile /absolute/path/profile
```

`$SKILL` 是此 skill 的绝对目录。优先复用已有 Playwright 安装；需要时用 `--playwright /absolute/path/playwright/index.mjs`。确实缺依赖才安装，不重复安装浏览器。

已有受控 context 时导入 `runWithContext(context, options)`，不要用占用中的同一 profile 再启动 Chrome。把长操作写入 `.mjs` 文件，控制通道只传短的模块导入调用；不要把大段中文脚本塞进 PTY 单行 JSON，之前会填满终端输入缓冲而卡住。

日志是 JSON 行。通过进程输出和状态文件读进度，不轮流截图所有页面。验证码出现时脚本置前对应页面并输出 `verification_required`，请用户完成本人验证；其他准备可以继续，不能绕过验证。

## 出错与续跑

- 点击发布前失败：最多自动重新准备一次。仍失败则由 agent 定位并修复具体原因后续跑，不无限重试，不把排查扔给用户。
- 点击发布后结果未知：标记 `publish_unconfirmed`，停止后续发布。先查后台确认，恢复状态后再续跑。**不得直接再次发布。** 续跑跳过 `submitted`、`reviewing`、`published`。
- 页面关闭/断开：先确认真实页面和进程是否存在，再恢复会话；不拿旧 page 句柄反复等待，不关闭用户无关浏览器。
- 页面结构变化：只修失败位置的选择器，必要时截一张错误截图，不重走整套探索。正常操作不截图。
- 合集仅补缺失作品，保留已有作品。通过集数旁的编辑图标、“填写集数”改序，不拖拽、不清空合集重建。统一保存并刷新确认一次。

最终简洁报告成功数、审核中或失败数、合集和顺序结果。
