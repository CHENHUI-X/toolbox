# Agent 框架识别

先从代码、Prompt、接口定义和测试确认框架；不要由 Agent 名称猜测，也不要从框架类型预设 case 场景。

## 工具调用 Agent

识别工具 schema、调用条件、参数来源、返回结构和输出协议。case plan 的可追溯链为：事实夹具 → Agent 可见输入 → 命中的规则 → 工具与参数 → 工具结果 → 输出。只有代码实际支持时才记录结构化输出、动作或多工具链。

## RAG Agent

识别知识库版本、检索 query 的形成方式、召回/重排结果、回答范围和引用协议。case plan 的可追溯链为：知识库版本 → Agent 可见输入 → 检索与召回结果 → 回答或规则要求的其他处理。不要编造工具参数、实时执行结果或不存在的引用。

## 工作流或状态机 Agent

识别初始状态、节点、转移条件、外部依赖、恢复规则和输出。case plan 的可追溯链为：初始状态 → 输入 → 命中的节点与状态迁移 → 节点结果 → 输出。只在当前实现存在状态时记录时间线。

## 路由或多 Agent 系统

识别路由依据、目标处理单元、交接信息和各单元的输入输出契约。case plan 的可追溯链为：可见上下文与输入 → 路由规则或模型结果 → 目标处理单元 → 交接或输出。历史中的每轮回复必须遵循其实际处理单元的规则。

## 纯生成或规则问答 Agent

识别 Prompt、静态资料、规则来源和输出限制。case plan 的可追溯链为：已知规则和资料 → 输入与上下文 → 输出。不要伪造不存在的工具、检索、状态或实时数据。

## 混合 Agent

按每条已确认 case 的真实路径依次建模。记录每一段输入、处理和证据，不要用“混合”标签跳过中间链路。
