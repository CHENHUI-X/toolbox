# 批量深挖执行（Batch Research Execution）

> 场景：用户（妈妈）发来探迹 Excel 名单并说"A档都查/都查了把"，要求把几十上百家公司全部调研，资料+话术填回名单 Excel。
> 实例：2026-08 深挖 185 家（A37 完整话术+邮件、B48 精简、C100 基础），全部填回名单 Excel 并 MEDIA 发回微信。

## 执行方式（踩坑后的可靠路径）

1. **别用 delegate_task 每任务查 6 家**——600s 超时，两次全挂（子代理模型处理慢 + DDG 不稳定）。每任务 ≤3 家才稳，或干脆不用子代理、自己用 execute_code。
2. **推荐：execute_code 自己批量抓**：
   - `from hermes_tools import web_search, web_extract` 循环。⚠️ hermes_tools 只能在 execute_code 里 import（terminal 的 python 没有该模块），抓取脚本一律走 execute_code；Excel 读写两边都行（terminal 缺 openpyxl 时先 `pip install openpyxl -q`）
   - web_search 每家 1 次，24 家/批 ≈ 70~190s 可行
   - **DDG 限流**（报 `DDGSException: No results found` 或越来越慢）时：改用 `web_extract` 抓百度百科，一次传 5 个 URL（`https://baike.baidu.com/item/{urllib.parse.quote(name)}`），25 家 ≈ 50s，明显更快更稳
   - 每批结果立即写 JSON 文件（`/root/.hermes/cache/documents/<批次>/batchN.json`），防 execute_code 超时被杀丢数据
3. **⚠️ 百度百科错位陷阱（必须处理）**：词条不存在的 URL 会返回其他内容/搜索页，返回顺序 ≠ 请求顺序。**必须从内容里提取 `^#\s*(.+)$` 标题行，建立 title→content 映射，再按公司名匹配**——否则资料张冠李戴（实例：44 条内容里 12 家错位）。
4. **⚠️ openpyxl 写入坑**：百科原文含控制字符（\b 等）→ `IllegalCharacterError`。写入 Excel 前必须 `re.sub(r'[\x00-\x08\x0b\x0c\x0e-\x1f\x7f]', '', text)`。
5. **信息有限的兜底**：搜不到的小微公司，经营内容填「公开信息有限，建议电话核实」，星级 ★☆~★★，标注"暂缓"，不要硬编资料。深挖前的两个替代信源：①**招聘信息是推断无官网小微主业的第一来源**——web_extract 抓职友集公司页（jobui.com/company/NNN）能出岗位名/驻地/规模/历年招聘，岗位名直接暴露细分主业（如「中低压采集运维工程师」=电力营销采集外包）；②爱企查/企查查桌面详情页是 JS 渲染，web_extract 只回脚本代码——工商事实（成立/地址/规模/经营范围）从 web_search 结果摘要里拼，别抓详情页正文。
6. **C 档也能捞到遗珠**：批量后人工扫一遍，制造类/专精特新/有融资的升 B（实例：久雅金融IT、本手OPPO系外包、商达政采分销、富迪IATF制造、嘉萌专精特新制造、成生鸿泉物联旗下）。
7. **档内避雷**：批量分级时对 A/B 档快速扫企查查风险栏——股权冻结/被限高/欠税公告/债权挂牌转让占两条 = 标"债务危机暂缓"或划掉，别给死企业写话术。

## 填回 Excel 的列布局（妈妈的主工具是名单 Excel，不是散文件）

- ⚠️ **列布局每次不同，先读表头确认实际列号再填**——新名单可能自带 法人/电话/跟进记录/分级 等列，话术列从最后一个已用列往后加；套用上一批的固定列号会覆盖原有数据

- 列 4「经营内容」：`【定位】【概况】【资产特征】【合作价值】星级【联系方式】【关键人】【切入角度】【风险】` 八段
- 列 9「电话话术」、列 10「微信验证语+开场白」、列 11「邮件模板」（A 档全给，B/C 精简）
- 话术按客户类型套模板：IDC型 / 硬件研发制造型 / 检测服务型（检测仪器台账+计量校准记录管理）/ 物联网平台型（自有设备+平台资产+客户设备打包）/ 央企国企型 / 软件科技型 / IPO并购型 / 竞品型（竞品只标"别推"不写话术）。类型判定按公司名关键词+查到的主业路由；大厂分公司留A档但话术须注明「采购权在总部，先核实本地决策权」
- 完成后验证统计（分级数/经营内容数/话术数），MEDIA 发回 Excel

## 第二批实例（2026-09-08 杭州为主名单）

- 400 家 → 划掉 21（运营商区县网点/广电营业部/邮电代办点/事务所分所）→ 保留 379：A55 / B273 / C51。杭州/上海名单里半导体、机器人、光电、检测仪器类比上批多，A 档占比明显高
- **百科命中率低时别死磕单家**：55 家 A 档首轮百科只中 17 → 立即换 web_search（每家 1 次「公司名 公司」+0.8s 间隔，分两轮跑，命中约 13/34）→ 剩余小微在 Excel 里填「公开信息有限，建议电话核实」，不要为单家反复重试
- A 档批量填的话术按类型路由（硬件研发型/检测型/物联型/央企型），话术列全部填通用骨架（夸→痛点→扫码即盘→免费试用→加微信），央企系另加「采购权在总部」提示
- 大厂分公司（中兴技术服务/长虹佳华/TCL/亚信/中船数字等）留 A 档但定位是「总部采购，本地无决策权」；母公司融资背景（如形弈科技=润芯微全资子公司，母公司近4亿B+轮）是价值信号，查公司时顺藤查母公司

## 逐家定制话术批量生产（用户点名"不要千篇一律/每家都写一份"时）

类型模板（同一话术骨架换公司名）会被否。可靠做法是**每家手写**，用 execute_code 分批跑（每批 15~30 家一个调用，变量字典直接写在代码里，写完立即存 JSON 防超时丢数据）：

1. **每家五要素**：`公司名（法人 电话）→ 主营 → 痛点 → 同行参考 → 话术`。主营/痛点一句话具体到这家（写"船舶靠港期短岸基设备散在多个港口"，不写"设备分散难管理"）；「同行参考」一行给效果数据（回收率95%+/盘点两周缩到两天/成本降三成），是话术可信度的来源。
2. **话术默认按"乐嵩格式"骨架**（单家范本被妈妈点名后成为批量默认）：称呼 → 夸赞一句但必须具体可查（奖项/资质/融资/标杆项目/上市代码；查不到的小微用行业年限共情如"做了21年"）→ "冒昧请教个事/问个实在事"带出一个场景化痛点提问 → "我们易盘点"三句产品价值 → 同行案例一行（效果数据）→ "免费试用，先试试不亏" → "方便加个微信吗"。全文 150~200 字，30 秒念完。夸赞切入点轮换（资质/融资/项目/年限）+ 痛点场景每家不同，模板感就没了——旧"开场五式"降级为痛点提问的措辞库，不再是话术骨架。
3. **称呼按法人姓氏**：话术开头"赖总/王总/邵经理"，从名单法人列取姓；法人缺失用"您好"兜底。
4. **同行业名单按细分方向拆钩子**：121 家全 IT/软件照样不重样——智能硬件类打工装治具/样机迭代，测试密集类打测试机墙/兼容库，驻场外包类打加密狗丢失/数据安全边界/备用机循环，大厂分公司打"总部系统管不到的本地弹性资产盲区"，成长期打"采购快于管理、离职设备核对"，信创类打适配测试设备量。先给名单分 sub 类再逐家写。
5. **地域专属钩子**：海南名单加台风季防灾盘点（资产提前扫码建档、灾后保险理赔一键导出台账）；山区/县域加服务半径远程核验；跨省分公司加"总部远程看账"。
6. **交付格式 = Excel**（妈妈明确点名要表格形式，别再默认 txt）：openpyxl 生成 xlsx，8列 `序号/公司名称/法人/联系电话/主营业务/痛点/同行参考/电话话术`，表头填色+白字加粗、正文 wrap_text+顶端对齐、话术列宽 ~80；话术单元格本身保持可直接复制的完整文本；MEDIA 发回。生成前先合并全部批次 JSON 再校验覆盖 N/N 并抽查实际内容——拿最后一个批次单独校验会误报缺失，tuple 序号对错会导致主营/痛点/话术错行。

## 名单补充字段（妈妈点名"补充法人/人员规模/是否上市/关键联系人部门"时）

- **法人批量搜索**：web_search `公司名 爱企查` 或 `公司名 法定代表人`（8 个 query 一个 execute_code 调用），从摘要抓「法定代表人为X」片段——命中率约四成，小微企业查不到标"待查"，别硬编。分公司/营业部/研究所 → 填总公司法人并注"(总公司法人)"。
- **是否上市**：知名企业直接写代码（如中粮糖业 600737、亚厦 002375、万事利 301066、碧水源 300070）；名单主体是上市母公司的分公司写"上市(代码)+母公司名"；其余"非上市"。
- **人员规模**：从搜索摘要拼（职友集"规模100-499人"、百科"员工979人"、参保人数）；分公司写母公司规模并注明。
- **企业性质按妈妈口径简化成三档**：央企/国企/私企（可带括号注集团系，如"国企（云南建投集团旗下）"），性质列红/黄底色区分；集团子公司两遍校验规则在 SKILL.md。
- **关键联系人部门映射**：证券/银行→综合管理部/办公室；保险→综合管理部/行政；建工类→设备物资部/工程管理部；央企能源制造→装备管理部/行政部；医疗→设备科/行政部；酒店→工程部；物业→综合管理部；传媒出版→综合办/制作管理部；产业园→园区运营部；研究院→条件保障部/资产处；央国企兜底→行政部/资产管理部；IT/科技→行政部/IT部。
- **列布局12列**：序号/公司名称/企业性质/是否上市/法人/人员规模/关键联系人部门/分层/补充信息/主营业务/痛点/同行参考/电话话术。
- **旧名单升级话术**（用户说"文档里的电话话术也按这个标准"）：不重查资料——从旧 Excel 读主营/痛点，只重写话术列到新骨架，其余列原样保留。

## 批量调研的交付习惯（用户偏好）

- 妈妈明确说过"你后台弄表格就行啦"——批量任务后台跑完再汇报，不要中途频繁打扰
- 完整交付 = 名单 Excel（资料+话术填好） + 必要时的速查卡 zip / 速查总表
- 深挖的公司资料同时存知识库 `易盘点客户/` 目录（每家一个 md）
- 妈妈事后单独点名名单里的某家要完整档案：法人/电话先从知识库里**已交付的名单 xlsx** 读，别指望 `/root/.hermes/cache/documents/` 的中间 JSON——cache 会被清理，已交付的 xlsx 才是持久的名单真源
